### Важные регрессии

- SQLite недоступна при первом приёме update: offsets **0 → 0 → 701**, update 700 сначала сохраняется в inbox, затем обрабатывается.
- Падение после работы с ledger, но до отметки inbox: вся финансовая транзакция откатывается, после перезапуска запись обрабатывается один раз.
- Повтор уже записанного поступления и параллельные distinct charges: один оплаченный заказ, отдельный учёт всех денег; ошибки outbox откатывают связанную запись.
- Подписанные неверные суммы, валюта, invoice/reference и владелец не переводят заказ в paid. Ошибка записи webhook возвращает 503 для повтора.
- Исторические записи/коллизии импортируются идемпотентно без новых уведомлений. Неизвестный исход создания счёта не приводит к выдаче URL или слепому перевыставлению.
- Браузер отправляет заявку в настоящий checkout helper на временной БД; ответ теряется **после commit**. Две попытки плюс перезагрузка и третья попытка дают одинаковое тело/request ID, **один order ID и один payment ID**. «Мои заявки» возвращает одну позицию.
- В одном browser context проверены preview, аккаунты 420/421, старый общий профиль, возврат в прежний аккаунт и очистка без удаления данных другого аккаунта.
- Каталог остаётся валидным после слишком длинного callback, отказа atomic replace и конкурентных добавлений.
